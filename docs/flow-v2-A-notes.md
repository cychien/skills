## Per item

1. **Order.** `guard_lib/order.py`. `todo from` stores `after` (item numbers) on each item; `todo done` refuses while one is open or waiting and names it; `todo list` shows `[after n]`. Phrases: "in parallel with step N", "beside step N", "in the same message as step N" (take N's dependencies; mutual references form one group), and, per amendment 1, "Starts after step N" / "steps N and M" / "N, M and K" (exactly those). `todo add` items have none.
   - **Deviation, flagged.** The spec's default "the previous item" orphans the step a parallel step pairs with: in 5 / 6 "in parallel with step 5" / 7, step 7 would depend only on 6, which depends on 4, so nothing after it waits on 5. I implemented the default as "every earlier step nothing waits on yet", which equals "the previous item" for any list without a parallel phrase, and makes a step after a parallel pair wait on both. With the amendment's explicit phrases the new feature flow does not depend on this; quick-feature, bug-fix and the old feature text do.
   - Before the amendment I had an interim "when step N hands back" phrase; it is gone, replaced by "Starts after".
2. **Proof of reading.** `guard_lib/proof.py`, `todo show <n>`. Attachments resolve against the principles skill beside the item's source skill, else the installed one; the index is the principles SKILL.md body without frontmatter. Token = first 6 hex of sha256(item text + attachment contents, in order). `todo done` on an item with a source needs `--token` (repeatable for `done 1 2`); a missing or stale token refuses with the show command. Showing records the attached principle stems in `principles_read`.
3. **Removed.** The unread-named-skill rule, the "every principle file" rule, and `uncited_principles`. `--not-run` is accepted, hidden from help, prints a deprecation line, and its `--reason` becomes the note. Reply, em dash, gates, mandatory, waits, own lists, skip cascade unchanged.
4. **Timed waits.** `todo hold --until <HH:MM|ISO> --reason`. HH:MM is its next occurrence; a past ISO time or bad format refuses. Stored per list (`hold`), so a subagent can hold its own list. While it lasts, the open-items stop rule passes. **Limitation:** in an autonomous run autorun's own stop hook still blocks ("run is not done"); I did not change autorun's stop handling. The autorun text tells the lead to hold; a background `sleep` until the reset is what actually wakes an autonomous session.
5. **`todo check`.** Exit 0 when nothing is open or waiting (an empty list passes), else 1 with the list. Read-only.
6. **Lint.** `guard_lib/lint.py`, `guard.py lint <name|path> [--all]`. "Installed beside" means the sibling folder, or in this repo's category layout any `skills/*/<name>` (installers drop the category). Errors and warnings as specified, plus the "Starts after" phrase.
   - **Narrowed, flagged.** Read literally, "a skill whose body mentions 'steps'" errors on four stepless skills that use the word in passing (eng-do "the design and grounding steps", principles "lifecycle steps", technical-writing "steps to a goal", guard "a skill's steps"). I treat it as "the body refers to its own steps": `step <number>`, "these/following steps", "steps below/above", outside code spans. With that, the repo has zero errors; one warning (verify step 7: "Close this step only when" with no backticked gate, workstream C's file).
7. **Hand-back size.** On a subagent stop with a final message over 300 words (CJK = half a word), block once per message length per agent id. **Addition:** the same rule on a PreToolUse of `SubagentHandback` (its `message`), because in Claude Code the hand-back travels in that tool call and the stop's last message may not carry it.
8. **Rerun while delegates run.** Any `verify.py rerun` (with or without `--only`) is denied while the session tracks a running subagent other than the caller (the existing delegate tracking from the leftovers sweep).
9. **PR before the close step.** `gh pr create` is denied while the lead's list has a skill item naming `../open-pr/SKILL.md` and an earlier item from the same skill is open or waiting. Applies to quick-feature and bug-fix too.
10. **Quota registry.** `guard_lib/quota.py`. `$ORCHESTRATOR_HOME/limits.json` (default `~/.agents/orchestrator`), written atomically under a lock, expired entries pruned on write and ignored on read. Post-tool scan only for Agent/Task/SendMessage results and shell commands whose command word is `codex`, `claude -p|--print`, or a `salvo.py` script (tokenized, so `grep codex`, `echo 'codex exec'`, quoted text and heredoc bodies do not count). Times: clock times ("3:05 PM", "5pm", "15:05"), ISO, month-day dates (a date wins), durations ("try again in 2 hours 5 minutes"), local zone, a parenthesized zone name ignored; no time means now + 60 min. **Additions:** Codex "try again in <duration>" and Claude's `usage limit reached|<epoch>` form. A Codex message with neither "try again at" nor "in" is not recorded (the spec requires the phrase).
    - **Risk:** an Agent hand-back that quotes a Claude limit message with a reset phrase (for example a report about limits) marks claude limited for an hour. That follows the spec; narrowing it would need a structural signal the payload does not carry.
    - `salvo.py` writes the same format itself (no import of guard, since salvo installs on its own) every time a run hits a limit, including limits it then waits out.
11. **Pick and spawn checks.** `quota status`, `quota pick --role --avoid`. `--avoid` takes `agent`, `agent:model`, or a full spec (prefix match), so a family can be avoided. Config: `<cwd>`, its git toplevel, then the main worktree's `.agents/orchestrator/models.json` (a linked worktree has no gitignored config), else `$ORCHESTRATOR_HOME/models.json`. Spawn checks deny `salvo.py run` with a limited entry and `codex exec` on a limited codex, with both roles' picks; native Agent spawns are not checked.
12. **Reserved subscription.** Runs `verify.py where` only when a command launches an agent other than the lead's. Plan: a `*.json` record in the verification directory whose value is a path ending in `plan.md` (works with B's adopt record whatever its key), else `<dir>/plan.md`. `- Agent: real` matched as a line prefix (amendment 4). **Interpretation:** plan lines do not name the agent, so a check's agents are those named (Claude Code / Codex) in its own section, else in the plan preamble, else all agents; minus the lead's agent. `verify.py rerun` commands pass. Any failure finding the plan passes.
13. **Fallback.** `quota pick --relax` prints the four-step order and walks it: strict; then the avoided entries of the same role (labelled "reviewer from a different family" for planner, "verifier on a different entry" for executor, since `--avoid` carries that separation); then the other role. A relaxed pick prints `relaxed: <rule>`. Stated in guard's SKILL.md.
14. **Tests.** `tests/test_guard.py`: one or more tests per item through the hook harness; `FeatureFlow` runs `todo from feature` on a ten-step fixture (asserts dependencies 6 with 5, 7 after 5, 8 after 6 and 7, mandatory set, exact gates, no `report --write` gate, and lint) and on `skills/eng/feature/SKILL.md` only once it has ten steps (superset gates); `test_every_skill_in_this_repo_lints_without_errors`. Guard and autorun SKILL.md, README line updated.
