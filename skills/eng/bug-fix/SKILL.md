# Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to subagents, and stay in the lead.

Paths like `../how/SKILL.md` point to skills installed beside this one, relative to this file's folder.

Be scientific. Every shipped line traces to runtime evidence. A belt-and-suspenders change that "might help" is a hypothesis, not a fix, and it does not ship. When evidence refutes a hypothesis, revert what it motivated.

Open a todolist whose first items are the steps below, copied in verbatim, before any task-specific todos. The `guard` skill's `todo from bug-fix` does this and orders the steps: step 7 opens together with step 6, step 8 starts after step 6, and step 9 starts after steps 7 and 8. Print each step with guard's `todo show <n>` before you work it, and close it with the token that prints. Without guard, use your agent's todo tool. A step you choose not to do stays in the list with a one-line `skip: <reason>`, so the user sees what was skipped and why.

**Keep the lead light.** Every lead turn resends the whole conversation, so the lead's context size multiplies the cost of every call it makes, and spent tokens turn into wall-clock time when the usage window runs out. When this session already carries a finished task (`../reflect/scripts/profile.py <transcript> --context` above 200k tokens), hand this task to a fresh owner subagent on your own model with a handoff brief, and only relay. Ask every subagent for a hand-back of at most 200 words with the details in a file you open only to audit. Pipe command output down to the lines you need, and mark todos in the same call that does the work. A usage limit moves a delegate to the next entry `python3 ../guard/scripts/guard.py quota pick --role <planner or executor>` prints, never to a wait.

1. Get the driver. Use the project's verification skill (`.agents/skills/verify-<app>/` or `.claude/skills/verify-<app>/`). Without one, run the **create-verification-skill** skill (`../create-verification-skill/SKILL.md`) in a clean worktree off main, so the driver learns the app as it is, not as a fix would make it. Close this step only when `../verify/scripts/verify.py driver` passes, which needs the verification skill on main or committed before any product change. Mandatory: no skip-with-reason escape.
2. Reproduce it yourself on main, on the surface where the user hit it. Mandatory: no skip-with-reason escape, because a fix for a bug you never saw is a guess. If it does not reproduce directly, synthesize the trigger, tighten the conditions, or instrument until it fires. Ask the user only with a specific reason the driver cannot reach the target, after driving it as far as it goes. Save the failing repro output as evidence. When a timing-dependent bug does not fire in three tries, stop repeating: log timestamps around the suspected window, then widen it on purpose (inject a delay) until it fires every time. Run the project's test suite on main once here too, so a pre-existing failure is known before any executor meets it. If it does not reproduce on main, say so and stop: it is already fixed or depends on state you have not found.
3. Binary-search the cause. List candidate hypotheses, seeded by the **how** skill (`../how/SKILL.md`) over the subsystem the bug lives in and the **why** skill (`../why/SKILL.md`) for regression history. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, and eliminate. When program state is unclear, add logging and read it as the code runs instead of guessing. Confirm the surviving mechanism with runtime evidence before planning a fix. When two fixes built on one premise have failed, apply the Attack the Premise principle (`../principles/references/principles/attack-the-premise.md`).
4. Write the verification plan per `../verify/references/plan.md`. Its first check is the repro from step 2, with the predicate it must meet once fixed. Add regression checks for the behavior next to the bug, and a perf check for any path a user waits on that the fix touches, with main as its baseline. Keep e2e to the repro and the core behavior no unit spec can see, because each e2e script starts a real instance on every rerun. Write the Drive contract from the names the repro drove on main. Close this step only when `../verify/scripts/verify.py plan` passes and `../verify/scripts/verify.py freeze` passes, so the predicates are fixed before the fix exists. Mandatory: no skip-with-reason escape.
5. Plan the fix. Read the principles index (`../principles/SKILL.md`), and read the file of each principle the fix applies before you cite it. Fix the root cause, not the symptom, per the Fix Root Causes principle (`../principles/references/principles/fix-root-causes.md`). If the fix crosses a function boundary, run the **architect** skill (`../architect/SKILL.md`) first. If it touches a shared primitive, a wire format, a schema, or a flag, run the **blast-radius** skill (`../blast-radius/SKILL.md`) on the planned fix now, because a risk found before the code costs a line.
6. Delegate the fix to a subagent on the executor model from the orchestrator config (`<project>/.agents/orchestrator/models.json`, falling back to `~/.agents/orchestrator/models.json`). Use a native subagent when your agent can run that model, otherwise the **salvo** skill (`../salvo/SKILL.md`) with that one entry, and apply its patch. Give it the root cause with its evidence, the file paths, and the plan's checks as success criteria. When the bug has a cheap local test path, the delegate writes a regression test first and confirms it fails for the reason step 3 found. Prefer no new test over a test of mocks, timing, or internals. Comments per the **code-comments** skill (`../code-comments/SKILL.md`). Give each independent bug its own executor, admitted by `verify.py capacity`. It runs no e2e check and writes no e2e script, because the verifier grades the fix. Spawn it in the same message as the next step's verifier. Close this step only when `../verify/scripts/verify.py units` passes. Mandatory: no skip-with-reason escape.
7. Write the e2e scripts, in parallel with step 6. Spawn the verifier from the **verify** skill's step 5 (`../verify/SKILL.md`), in its own worktree at main, from the plan and the driver only. Its dry run on main with `verify.py dryrun` is the repro again as a script. The repro check must reach `verify: ready` and fail its predicate there. A light model then compares each script with its check, and every drift goes back to the verifier. Start any native-app instance the plan needs in the background now, and reuse it through the driver's sync. Close this step only when `../verify/scripts/verify.py scripts` passes. Skip this step with the reason only when the plan has no e2e check.
8. Review the fix. Starts after step 6. Follow the verify skill's step 6: a fresh reviewer in Mode `change`, every finding triaged, each `fixed` one fixed by the executor and proved by a unit spec with no e2e run, then the same reviewer once more in Mode `fix`, with the section's `Fixed at:` line written once its fixes land. Close this step only when `../verify/scripts/verify.py review` passes. Mandatory: no skip-with-reason escape, because review fixes must land before the e2e run so they never void it.
9. Prove every check in the plan with the verify skill, on the reviewed fix. Starts after steps 7 and 8. Use one full `verify.py rerun` by the same verifier, `verify.py units`, `observations.md`, and `report.md` built with `python3 ../verify/scripts/verify.py report --write --author <executor agent:model> --verifier <verifier agent:model>`, plus `--note "<text>"` for each quota fallback that relaxed a separation rule. The repro must fail on main and pass on head. A unit test shows branch behavior, not that the bug is gone. Close this step only when `../verify/scripts/verify.py oracles` passes. Mandatory: no skip-with-reason escape, because the author's own run is not a verdict.
10. Fix the e2e FAILs per the verify skill's step 11: classify each FAIL first (product, script or driver, environment, premise), let every fix group hand back, then rerun once, every e2e check when a fix changed product code. Grade each fix with that rerun and `verify.py units`, never with a fresh verifier, at most 2 failed attempts per check. Skip this step with the reason when nothing failed.
11. Rebase into small, ordered commits with the failing repro or regression test before the fix, per the Sequence Work into Verifiable Units principle (`../principles/references/principles/sequence-verifiable-units.md`), keeping the tree the e2e run graded.
12. Close, then the PR. Run `verify.py units` once more after the rebase. Close this step only when `../verify/scripts/verify.py report` passes and `../verify/scripts/verify.py leftovers` passes. Run the **open-pr** skill (`../open-pr/SKILL.md`). A PR may open with FAIL or INCONCLUSIVE checks, which open-pr lists at the top under the `do not merge` label. Mandatory: no skip-with-reason escape.

**Reply:** what was broken, the root cause with its evidence, the fix, the verify skill's check table, and every review finding with its triage. Paste the failing-then-passing repro output verbatim. Write it per the **reply** skill (`../reply/SKILL.md`). End with the run's profile from `../reflect/scripts/profile.py <transcript> --since '<first words of the task prompt>' --record <task label>`: wall time, idle time, agents, and tokens, so every run is measured against the last.
