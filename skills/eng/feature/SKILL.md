# Feature

**You own the design. Plan, review, verify.** Delegate implementation. Stay in the lead.

Paths like `../how/SKILL.md` point to skills installed beside this one, relative to this file's folder.

Open a todolist whose first items are the steps below, copied in verbatim, before any task-specific todos. The `guard` skill's `todo from feature` does this; without guard, use your agent's todo tool. A step you choose not to do stays in the list with a one-line `skip: <reason>`, so the user sees what was skipped and why.

1. Clarify the requirements and what proves them. Review the feature spec and list what it leaves open that the user will see or rely on: inputs, outputs and their format, behavior at the edges, and scope. Alongside it, draft the verification plan per `../verify/references/plan.md`, with perf acceptance, the seed data each check needs, and an oracle check for every value computed from data, because each pass predicate and budget states a requirement in checkable form. Each open item, predicate, and budget is a product decision, and making it yourself builds your guess instead of their feature, so discuss both with the user before designing. Settle an item a run can answer (a layout, a timing, which approach works) with the **prototype** skill (`../prototype/SKILL.md`) first, so the discussion is over evidence instead of guesses. A spec that settles every item, predicate, and budget needs no discussion. Then write the plan file and add each check to the todo list as its own item, so none can drop silently. Close this step only when `../verify/scripts/verify.py plan` passes. Mandatory: no skip-with-reason escape, because every later step builds and verifies against this plan.
2. Read the **principles** skill (`../principles/SKILL.md`) and every principle file it indexes. Mandatory: no skip-with-reason escape, because the principles shape every later step and a citation is only honest when its file was read.
3. Run the **how** skill (`../how/SKILL.md`) over the affected subsystem.
4. Run the **architect** skill (`../architect/SKILL.md`) for parallel design exploration. When the candidates split on a premise a run can check, settle it with the **prototype** skill (`../prototype/SKILL.md`) instead of letting the judge guess. When the designs or a prototype show that a pass predicate is wrong or missing, revise the plan with the user per `../verify/references/plan.md`.
5. Write the throughput checkpoint as four todo items. A dimension that genuinely does not apply (single file, no fan-out) keeps its item with `n/a: <reason>` rather than being dropped:
   - **Blocking first steps.** Gates run before fan-out.
   - **Independent workstreams.** Disjoint files, services, or layers parallelize. Shared writes serialize.
   - **Shared mutable state.** Default to splitting the target (the Separate Before Serializing Shared State principle (`../principles/references/principles/separate-before-serializing-shared-state.md`)). Serialize only for real invariants.
   - **Smallest safe decomposition.** If one worker is best, name why.
6. Get the driver before any code for this change exists. Use the project's verification skill (`.agents/skills/verify-<app>/` or `.claude/skills/verify-<app>/`). Without one, run the **create-verification-skill** skill (`../create-verification-skill/SKILL.md`) in a clean worktree off main, because a driver built after the change learns the change's behavior as the app's and stops catching its bugs. Close this step only when `../verify/scripts/verify.py driver` passes, which needs the verification skill on main or committed before any product change. Mandatory: no skip-with-reason escape.
7. Delegate code-writing to a subagent on the executor model from the orchestrator config (`<project>/.agents/orchestrator/models.json`, falling back to `~/.agents/orchestrator/models.json`). Use a native subagent when your agent can run that model, otherwise the **salvo** skill (`../salvo/SKILL.md`) with that one entry, and apply its patch. Give it a specific scope (file paths, named data shape and its organizing structure per the Model the Domain principle (`../principles/references/principles/model-the-domain.md`), a state machine over scattered booleans, a table/registry over branching, a typed model over repeated shape assumptions, chosen before the delegate writes logic, and success criteria: the plan's checks, with its unit tests written to fail first). When the implementation admits multiple valid shapes (error handling, abstraction layer, test structure), delegate via the **arena** skill (`../arena/SKILL.md`) instead so the runners surface the alternatives and the cross-judge guards the pick. Mandatory: no skip-with-reason escape, and Laziness Protocol does not override it (the gain is review separation, not lines saved). A subagent forbidden to spawn satisfies this by owning the diff directly with the same review separation. No "standing by" reply that waits on a nested agent. Comments per the **code-comments** skill (`../code-comments/SKILL.md`). Surgical edits, re-ground against the source for upstream-derived files. Port shared-primitive improvements to all consumers and verify each. Commit liberally.
8. Prove every check in the plan with the **verify** skill (`../verify/SKILL.md`): a fresh verifier drives the change on its matching surface, such as a CLI in a real terminal or a web UI in a real browser through chrome-devtools-axi, and you audit its evidence. Mandatory: no skip-with-reason escape, because the author's own run is not a verdict. "Inconclusive" or wrong-surface is not a pass. Flag it. Close this step only when `../verify/scripts/verify.py report` passes. On a FAIL, delegate the fix to the executor at its root cause, then run the verify skill again for the checks the fix could touch, with a fresh verifier.
9. Rebase into small, ordered commits. Stack follow-ups.
   Use the Sequence Work into Verifiable Units principle (`../principles/references/principles/sequence-verifiable-units.md`), building, verifying, and committing each small unit before the next.
10. If the design is contested, run the **interrogate** skill (`../interrogate/SKILL.md`) before shipping. If the change reaches past its diff (a shared primitive, a wire format, a schema, a flag), run the **blast-radius** skill (`../blast-radius/SKILL.md`).
11. Run the **open-pr** skill (`../open-pr/SKILL.md`).

Code-coupled work (one feature, one migration) goes to a single owner with the checkpoint inline. That owner fans out internally after the blocking phase. Parent-level fan-out is for slices that produce independent artifacts (audits, cross-subsystem investigations, competing experiments). Rewrite the checkpoint at phase boundaries. Spawn a fresh owner rather than chaining interrupts.

**Reply:** what you built, what you chose and why, the throughput checkpoint, the verify skill's check table, every exploration finding with its triage, open decisions. Tables for design alternatives. Write it per the **reply** skill (`../reply/SKILL.md`).
